The implanted bugs

policy-targeted app/game.py

In the mine-reveal path of reveal(), the emit order was swapped so mine.boom is now emitted BEFORE the mine cell's board.reveal (it used to be emitted after). A developer might reorder these to 'detonate first, then record the reveal'.

Expected effect: On every losing game (a mine revealed), a board.reveal event for the mine cell is now emitted after the mine.boom event, so a cell is revealed on the board after the board has detonated.

blind-spot probe app/game.py

Off-by-one in the win check: the target was changed from '== rows*cols - mines' to '>= rows*cols - mines - 1', so the board is declared won (and the terminal game.done is emitted) one safe cell early, before all non-mine squares are cleared.

Expected effect: Games declare victory and emit the terminal game.done one reveal too soon; a game that is not actually cleared is reported as won. No policy asserts on win/game.done correctness, so this is a likely monitor blind spot.

Blind user (monitor only)

An agent that never saw the ground truth, working only from the monitor:

  • Off-by-one in the win condition: _check_win uses `len(self.revealed) >= self.rows * self.cols - self.mines - 1` (threshold 53) instead of `- self.mines` (54). The board is declared 'won' when only 53 of the 54 non-mine squares are revealed, leaving one safe square permanently covered. Because winning flips status to 'won', the frozen-board guard then blocks revealing that last square. The monitor surfaced this two ways: (1) the replay_check.py gate reported MISMATCH (91 verdicts vs pinned EXPECTED 92) because the dropped final cell.reveal removes one per-cell monitored entity from the healthy game; (2) the `catalog diff --fail-on-app-risk` stability check FAILED with an app behavior-risk flagging _check_win/reveal as changed logic on every emit path. Reproduced directly: healthy game ends status=won, revealed=53 of 54, unrevealed_safe=1. via both

The 3 injected cheat streams (reveal-after-boom, double-reveal, flag-overflow) each violated as designed — those are the expected 3 violations and are NOT bugs. The single genuine defect is the healthy game's premature win. Note the reveal-after-boom violation's deciding events show the real engine emits mine.boom BEFORE board.reveal for the mine cell (reveal(): _emit_boom then _emit_board_reveal); that ordering is what the injected cheat targets and appears intentional per the code comments, not a separate bug. The replay gate exit code was 1 (verdict-count mismatch), and the stability gate exit was non-zero (6 behavior-risk breaks). Only one root cause: the `- 1` on game.py line 212.
