The implanted bugs

policy-targeted app/blackjack.py

In stand(), the payout branch was changed from `elif outcome == "push": self._pay(BET)` to a bare `else: self._pay(BET)`. This looks like a plausible 'if you didn't win, return your stake' refactor, but it now pays out BET on a LOSING hand too, not just on a push. A hand that settles as "lose" (e.g. the scripted healthy-loss hand: player 17 stands, dealer 20) now emits hand.settled(outcome=lose) immediately followed by hand.payout.

Expected effect: A losing hand receives a payout. The real BlackjackTable now emits a PAYOUT after a SETTLED(lose) on the healthy losing-hand path, violating policy 05 (a hand settled as "lose" is never paid out). Push and win behavior is otherwise unchanged.

blind-spot probe app/blackjack.py

In stand(), the winning payout amount was changed from `self._pay(BET * 2)` to `self._pay(BET * 3)`, an overpay to the winner (plausible confusion with a 3:2 / bonus payout rule). The payout event is still emitted correctly after settlement, only the amount field is wrong.

Expected effect: Winning hands are paid 30 chips instead of the correct 20 (BET*3 instead of BET*2). The house overpays every winner. No policy inspects the payout amount (STEPS.md exposes only 'a payout is made for the hand' with no amount parameter), so this is a monitor blind spot.

Blind user (monitor only)

An agent that never saw the ground truth, working only from the monitor:

  • In app/blackjack.py, BlackjackTable.stand() pays out on a LOSING hand. After settling the outcome it does `if outcome == 'win': self._pay(BET*3) else: self._pay(BET)` - the else branch covers both 'lose' and 'push', so a stood hand that loses emits a hand.payout right after settling 'lose'. In blackjack a loss pays nothing. This violates policy 05 'a hand settled as a loss is never paid out'. The monitor caught it as unexpected violations on healthy hands H-4 (a plain losing hand: player 17 vs dealer 20) and H-7 (the rule-5 terminal-window probe, a real losing hand), turning the CI replay gate red (exit 1, 8 violations vs 6 expected). Note the bust/hit() loss path correctly pays nothing; only the stand() loss path is buggy. Fix: only pay on win (and optionally push to return the bet), never on lose. via both

The monitor surfaced the bug two independent ways: (1) runtime replay gate went red - exit 1, MISMATCH 8 violations vs pinned 6, with explicit 'violated' verdicts + rendered lose-then-payout explanations on H-4 and H-7; (2) the catalog diff --fail-on-app-risk stability check flagged BlackjackTable.stand/_pay with 'policies at risk: a hand settled as a loss is never paid out'. The seeded cheats A-E and the three terminal-window probes behave exactly as their intended narration describes; the only anomaly is the two extra rule-5 violations from the stand() loss-payout bug. No other policy (rules 1-4) showed unexpected verdicts. I did not open ground_truth/.
