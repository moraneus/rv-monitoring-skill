The implanted bugs

policy-targeted app/game.py

In _close_attempt, when the winning pair completes the board (len(matched)==BOARD_SIZE), an early 'return' was added right after self._complete(), so the final matched attempt's attempt.resolved event is never emitted.

Expected effect: The last (game-winning) attempt flips its second card (arming rule 2's per-attempt 3s 'within' deadline) but never resolves. The deadline lapses and rule 2 (02_attempt_resolves_within_3s) fires a violation for the final attempt of every completed game. In the healthy demo game (all matches) the winning attempt hangs.

blind-spot probe app/game.py

In resolve_mismatch, the outcome string passed to _resolve was typo'd from 'mismatched' to 'mismatch', so mismatched attempts emit attempt.resolved with payload outcome='mismatch'.

Expected effect: The attempt.resolved event still fires (so rule 2's within-3s deadline is satisfied), but its outcome payload value is wrong. No policy binds attempt.resolved.outcome to a value, so the corrupted enum passes silently - a monitor blind spot.

Blind user (monitor only)

An agent that never saw the ground truth, working only from the monitor:

  • The game-completing match never emits an `attempt.resolved` event. In `app/game.py` `_close_attempt` (lines 136-139), when the last pair matches the code calls `self._complete()` and `return`s BEFORE reaching `self._resolve(attempt_id, "matched")`. So every game's final attempt flips its second card (arming rule 2's 3-second deadline) but is never resolved, leaving the deadline to blow. The runtime gate surfaced this as two unexpected `an attempt resolves within 3 seconds` violations in supposedly-healthy games (G1-a9 @ t=8.0, G2-a8 @ t=14.5) plus one `pending` instance of the same defect (G4-a8, pending only because it's the last game and nothing advanced event-time past its deadline).
