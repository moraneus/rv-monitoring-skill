What it is

A brownfield service, instrumented additively

A ParcelService written long before monitoring existed. The agent added an injected emit/clock with no-op defaults, so legacy callers run byte-identically - instrumentation sits beside the logic, never reshaping it.

Delivery is deliberately NOT a terminal event: rule 2 must keep watching a parcel after delivery to catch a later reroute, so finished parcels are reclaimed by a TTL instead.

event model  · one type parcel.status keyed by parcel_id; register / hub_scan / out_for_delivery / deliver / route_to / return_to_sender.

The sabotage

The bug planted in the app code

Bug 1 - route_to emits a lying status

  def route_to(self, id, hub):
      parcel.status = "rerouted"          # internal state is CORRECT
-     Event(..., {"status": "rerouted"})  # but the event...
+     Event(..., {"status": "scanned"})   # ...reports the wrong status

The parcel's internal state stays right; only the emitted event lies, reporting scanned where a reroute happened. Rule 2 (a delivered parcel is never re-routed) watches for a rerouted event that now never arrives, so a reroute-after-delivery is never detected by the live monitor - the rule-2 card stays empty and green.

Policy in play: 02 - no reroute after delivery (goes dark)  ·  Trigger: deliver(P) → route_to(P, hub)  ·  Class: normal-use

Detection

How the failure surfaced

The same defect through the framework's three independent channels, plus what the blind user actually noticed.

Channel A - live runtimemiss · dormant

Rule 2's dashboard card stayed empty for the rerouted parcel. A delivered-then-rerouted parcel - the exact nightmare the rule exists for - produced no verdict at all. The single most important rule silently stopped watching.

Channel B - replay gatered · exit 1

replay_check.py failed: expected 3 violations, got 2 - the reroute fault stayed pending instead of violating, so the pinned count dropped and the gate went red.

Channel C - stability contractrisk · exit 1

catalog diff flagged route_to#1 as behavior-risk (emit slice changed) against all three policies - a good tripwire, but only a soft risk: the contract fingerprints payload field NAMES, not the constant value, so "rerouted"→"scanned" degrades to a risk rather than a break.

The blind userfound 1 / 1

Caught it two ways - by reading the source and by running the deterministic replay gate - and correctly diagnosed that the live monitor was masked because the committed trace still held the old value. Careful enough to back up and restore the trace it perturbed.

The runtime cards are not the whole monitor. When a bug makes the emitter lie about a status a rule keys on, the live verdict goes dark - but the pinned replay gate and the two-sided stability contract are exactly the backstops that caught it. This is the demo that most argues for using all three channels.
