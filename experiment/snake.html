What it is

A browser Snake with an embedded monitor

A stdlib HTTP server serves an inline canvas game; the engine emits events to a live dashboard. A session ends when the snake hits a wall or itself.

A game entity is deliberately non-terminal so the post-over prohibitions stay armed.

event model  · game.status, game.move (carrying direction + prev_direction), game.food, game.grow - all keyed by game_id.

The monitored rules

What the user asked the monitor to enforce

Verbatim from the committed monitoring/policies/. These are the human's own words; the engine owns the verdict.

Feature: the snake never reverses straight into itself Scenario: a 180-degree reversal is never accepted Then the snake reverses into itself never happens
Feature: every point scored makes the snake grow in time Scenario: food eaten is followed by growth within two seconds When food is eaten Then the snake grows within "2" seconds
Feature: no play after a game is over Scenario: a finished game never moves again Given a game is "over" Then the snake moves never happens

The sabotage

The bugs planted in the app code

Bug 1 - the reversal guard is dead code

  def set_direction(self, direction):
-     if OPPOSITE[self.direction] == direction:  # blocks a 180° turn
+     if OPPOSITE[direction] == direction:       # always False
          return False

The guard compares a direction to its own opposite - always False - so a 180-degree reversal straight into the snake's neck is accepted. Press the opposite arrow and you instantly die. The monitor catches this: the reversal rule fires live.

Policy in play: 04 - no reversal  ·  Trigger: moving right, press Left (one keypress)  ·  Class: normal-use

Bug 2 - eating food never grows the snake

  def tick(self):
      ... move, maybe eat food, emit game.grow ...
-     if not grew: self.snake.pop()   # keep tail unless growing
+     self.snake.pop()                # ALWAYS pop - never grows

An unconditional tail-pop: the snake scores points and emits a game.grow event, but its length never actually changes. Rule 2 checks only that a grow event followed the food within 2 seconds - which it did - so the card stays green. The monitor watches the event, not the world.

Policy in play: none effectively - the event fires, so 03 is satisfied  ·  Trigger: eat any food  ·  Class: subtle · slip-through

Detection

How the failure surfaced

The same defect through the framework's three independent channels, plus what the blind user actually noticed.

Channel A - live runtimecatch + miss

Rule 3 (no reversal) went red on real games where the player reversed. But rule 2 stayed green while the snake never grew - the grow event fired on schedule even though the length was frozen.

Channel B - replay gatepass · exit 0

The pinned gate passed - because the scripted traffic injects the reversal as a raw event and its healthy game only checks that the grow event fired, so neither buggy engine path is actually exercised. A methodology lesson: seeds must drive the real engine.

Channel C - stability contractbreak · exit 1

catalog diff failed, flagging set_direction and tick as changed on the emit path.

The blind userfound 2 / 2

Drove the game over HTTP: reversed the snake and watched rule 3 fire, then noticed the length stayed at 3 while the score climbed to 16 - catching the grow bug by eye that the monitor could not see.

A monitor watches events, not state. When the bug is in the logic the event reports (a reversal accepted), the monitor is excellent. When the bug is a lie between the event and reality (a grow event with no growth), only a human watching the actual game catches it - and the pinned gate can pass while the live game is broken if its traffic bypasses the real path.
