The implanted bugs

policy-targeted app/game.py

The tick() guard was weakened from `if self.over or not self._started` to `if not self._started`, dropping the game-over check. A finished game (over == True) is no longer inert: any further tick() call still advances the snake, emits a game.move, re-hits the wall, and emits another game.status 'over'. Plausible refactor assuming callers stop ticking a dead game.

Expected effect: For the engine-driven healthy games (g-clean, g-turn), the traffic runs a fixed 12 ticks but the game reaches the wall ('over') around tick 10, so ticks after death now emit game.move events AFTER a game.status='over'. This violates policy 01 (no moves after a game is over) for those entities, adding unexpected violations beyond the 4 expected.

blind-spot probe app/game.py

The tail-pop was changed from `if not eats: self.snake.pop()` to an unconditional `self.snake.pop()`. On eating, the head is inserted, a game.grow event is emitted with the pre-pop length (so the payload still looks correct), then the tail is popped anyway, leaving the snake's actual length unchanged. Growth is silently broken while the grow event keeps firing.

Expected effect: The snake never actually grows after eating food (length stays constant), yet a game.grow event is still emitted after each game.food. Because policy 03 only checks that a grow EVENT follows food within 2s (not that length increased), and no policy checks the snake's length, this behavioral corruption is invisible to the monitor.

Blind user (monitor only)

An agent that never saw the ground truth, working only from the monitor:

  • SnakeGame.tick() in app/game.py is missing an `if self.over: return` early guard (set_direction() has the analogous guard, tick() does not). After the game ends at a wall collision, further tick() calls still execute the move logic and emit a game.move event AFTER the game.status=over event. This violates policy 01 ('a finished game never moves again'). It fires on the normal healthy games g-clean and g-turn (which run a fixed tick loop that continues past the game-over) and adds a spurious move-after-over violation to g-point-after-over. The replay gate expected 4 violations but got 7 (3 extra), and the stability diff independently flags game.SnakeGame.tick as a changed emit-path behavior risk. via both

The 4 injected faults (move-after-over via raw event, point-after-over, food-without-grow, 180 reversal) are intentional test corruptions and produce exactly their expected 1 violation each - those are not app bugs. The single real app bug is the missing over-guard in tick(), which manifests as 3 unexpected violations (2 on healthy games g-clean/g-turn, 1 extra on g-point-after-over) and as the tick() emit-path behavior risk in the catalog diff. Both the replay gate (exit 1, verdict/violation mismatch) and the stability check (exit 1, app behavior risk) independently surfaced it. I did not modify any files and did not read ground_truth/.
